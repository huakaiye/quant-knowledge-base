## 1. 新手摘要

这次实验想知道：8WGC 已经证明 Windows Python、QMT userdata 路径和配置校验都能通过，但 `xttrader.connect()` 返回 `-1`，没有生成真实 dry-run JSON。7X8F 不再盲目重跑 dry-run，而是把连接失败拆成可审计前置条件：客户端进程是否存在、userdata 是否近期活跃、账号目录是否存在、xtquant 模块是否可导入、日志是否 stale、后续重跑命令是否明确。

我们原本预计：如果问题主要是 QMT 客户端未启动或未登录，那么诊断应显示 `qmt_process_found=false`，并且 userdata/log 最新修改时间明显早于当前时间；如果问题是 Python 或 xtquant 环境，则应在模块导入或子模块检查中失败。

实际看到：诊断输出 `overall_status=qmt_client_process_not_found`。配置、账号、`qmt_path`、`users/8886008880`、`MiniConfig.xml`、Python 3.11 下 xtquant 模块都通过；唯一 required failure 是 `qmt_process_found`，候选 QMT 进程数为 0。userdata 最近文件新鲜度通过，说明目录近期被写过，但当前没有可识别的 QMT/MiniQMT/xtquant 交易客户端进程。

这说明：8WGC 的 `connect=-1` 不应继续解释为 hard5 策略问题，也不是 Python/xtquant 包缺失。当前最小必要动作是启动并登录国金 QMT 模拟客户端，使交易客户端进程和账号会话可见，然后再重跑 `--connect-check` 和 `--dry-run-once --output-json`。

但还不能说明：即使诊断通过，也只能说明具备重新跑 `--connect-check` 或 `--dry-run-once` 的前置条件；它不能说明 hard5 修复机制有效、不能改 hard5、不能提交真实委托。

下一步要做：实现并运行只读诊断脚本；若诊断仍显示客户端未运行或 userdata stale，则把下一步收敛为“启动并登录国金 QMT 模拟客户端后重跑 8WGC 命令”；若诊断显示环境已就绪，则重跑 connect-check 和 dry-run once。

## 2. 研究背景

QS5G 已经暂停日频和分钟路径阈值路线，要求后续只走真实 dry-run JSON、订单生命周期、盘口/逐笔或成交滑点证据层。8WGC 是第一轮真实 dry-run 尝试，但失败在 MiniQMT 连接层：`xttrader.connect()` 返回 `-1`，未生成 `live_dry_run_once.json`。当前最小不确定性不是“要不要继续调 hard5 阈值”，而是“当前机器为什么不能采集真实订单层 JSON，以及下一次重跑前应该检查什么”。

## 3. 实验前假设

如果 8WGC 的失败主要来自 MiniQMT 客户端未启动、未登录或 userdata 会话过期，那么一个只读连接诊断脚本应能在不连接、不下单的情况下，把阻塞定位到客户端进程、userdata 活跃度、账号目录或 xtquant 模块环境中的至少一个前置项。

## 4. 实验前预测

如果假设为真，应该看到：

- 指标：输出 `qmt_connection_diagnostic_summary.json`、`qmt_connection_checks.csv`、`qmt_recent_files.csv` 和 `qmt_processes.csv`。
- 环境：`C:\Python311\python.exe` 存在且为 Python 3.11；配置中的 `qmt_path` 存在。
- 客户端状态：若 QMT 未启动，`qmt_process_found=false`，并把 `process_gate` 标为失败或阻塞。
- userdata 状态：若最近日志和核心文件时间远早于当前时间，`userdata_fresh_gate=false` 或 warning。
- 模块状态：若 `xtquant.xttrader/xtdata/xtconstant/xttype` 可导入，说明失败更可能在客户端会话，不是 Python 包缺失；若不可导入，则阻塞在 Python 环境。
- 安全边界：脚本不调用 `xttrader.connect()`，不查询账户资产，不提交委托。

## 6. 竞争性解释

即使诊断显示 QMT 进程不存在，也可能是：

- 客户端进程名不含 QMT、MiniQMT、XtMini 或国金关键词，导致只读进程扫描漏报；
- userdata 最近未写入，但客户端已启动，只是尚未登录或未打开交易模块；
- xtquant 模块可导入，但账号与当前客户端会话不匹配；
- 账号目录存在，但不是当前登录账号；
- 日志编码不是 UTF-8，关键词扫描可能低估真实错误。

## 7. 证伪条件

出现以下情况，本实验不通过：

- 脚本不能在无 QMT 连接的情况下运行；
- 脚本需要真实下单确认、连接账户或调用 `xttrader.connect()`；
- 输出不能区分 required failure 与 warning；
- 输出没有给出后续重跑命令；
- 诊断结果被写成策略收益或 hard5 修改依据。
