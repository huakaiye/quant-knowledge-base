## 1. 新手摘要

这次实验想知道：A22 过去到底在哪些日期、哪些变体和哪些样本段真实触发过，而不是只看到工程门禁通过。

我们原本预计：历史四段里能找到 A22/A13 预算触发日志，但 2026-05-20 之后，特别是 LWC4 和 8UP9 的近端 forward/OOS 窗口，真实触发会很少或为 0。

实际看到：脚本扫描 47 个 A22 相关 `logs.jsonl`，生成 `3687` 行事件索引；历史可见 A22 live budget 行 `98` 行，去重触发事件 `49` 行，最新 live/shadow 触发交易日都是 `2026-05-19`。2026-05-20 之后 `21` 条 shadow 记录全部是 `no_hot_score_target`，真实触发为 `0`。

这说明：A22 的历史优势仍主要来自设计前历史四段；LWC4 和 8UP9 的近端 forward/OOS 样本只证明观察链路干净，不提供真实触发收益证据。A22 不能靠继续滚动无触发短窗来推进。

但还不能说明：即使找到历史触发，也不能直接证明 A22 可以上线；这只是定位可验证事件，不是收益回测、实盘 dry-run 或未来函数最终审计。

下一步要做：扫描已有 A22 相关 `logs.jsonl` 和 run 日志，生成触发事件日历；若没有后设计期真实触发，停止继续滚动短窗收益门禁，转为等待实盘 dry-run 或新增数据后的事件驱动验证。

## 2. 研究背景

本实验属于 H6V3 双池轮动 score 过热拥挤机制模块。用户提出当前策略方式滞后性太大，并希望从 R 方以外的顶刊拟合方式寻找灵感。前序中，A22 cap70 的历史收益闭环、原生字段等价、forward/shadow 工程隔离都较完整，但 YA5R、LWC4 和 8UP9 的近端 observe/forward 样本均没有真实 A22 触发。

8UP9 已经证明继续按日历滚动近端短窗容易退化为“工程干净但无触发”。因此本轮不再跑新回测，而是建立 A22 真实触发索引：先回答触发在哪里，再决定是否存在未设计 forward/OOS 收益门禁样本。

## 3. 实验前假设

已有平台日志足以复原 A22/A13 预算触发事件日历；如果后设计期和近端 forward/OOS 中真实触发不足，则 A22 的下一步不应继续滚动短窗回测，而应等待实盘 dry-run 或新增触发事件。

## 4. 实验前预测

如果假设为真，应该看到：

- 指标：扫描到的历史触发事件主要来自 A22N/QTFV 等历史四段，LWC4 和 8UP9 近端窗口的 shadow trigger 计数为 0。
- 交易行为：本实验不生成交易，不改变订单，只读取既有日志。
- 风险表现：不产生收益、回撤或成本新指标；只输出事件计数、窗口覆盖和证据等级。
- 分段表现：若 2026-05-20 之后没有真实触发，则不再把 2026-05-20 之后的无触发日历窗当成 A22 收益证据。

## 6. 竞争性解释

即使结果符合预期，也可能是：

- 日志命名里 legacy A13 与 native A22 同时存在，需要区分字段语义等价和真实 native 字段触发。
- 有些历史触发只出现在正式 live 预算路径，不出现在默认关闭 shadow 近端路径，不能直接外推到实盘 observe。
- 近端没有触发可能只是市场状态短期不匹配，不等于 A22 机制无效。
- 只读扫描依赖既有日志完整性；如果历史 run log 被清理，只能说明可见日志中未找到，不代表平台从未触发。

## 7. 证伪条件

出现以下情况，本假设不通过：

- 扫描脚本不能稳定解析 A22/A13 预算触发和 shadow 记录，或出现大量不可归类日志。
- 8UP9/LWC4 中发现与已汇总结论冲突的真实触发，说明上一轮无触发结论需要重审。
- 发现 post-design 真实触发样本，但脚本无法定位对应配置、结果和日志路径，不能形成可复核事件清单。
- 结果只输出计数、不输出事件级证据路径，无法支持下一步实验选择。

## 14. 反对证据

- YA5R 和 QTFV 的非 gate-relevant cross check 中，summary 期望记录数与脚本扫描总数不完全一致；原因是 7Z32 扫描完整四段/多 run，而对应 summary 中的期望值是局部聚合。该差异不影响 LWC4/8UP9 近端 gate 结论，但说明不能用 7Z32 单独重写 QTFV/YA5R 历史汇总结论。
- 近端没有触发不等于 A22 机制无效；只能说明当前 post-design 可见样本不能提供真实触发后的收益证据。
- 本机 `${LIVE_TRADING_ROOT}` 未配置，仍不能替代真实实盘 dry-run 或委托成交日志。

## 15. 偏差诊断

实验前预测大体成立：历史四段能找到触发事件，LWC4/8UP9 近端窗口为 0 触发。一个需要说明的差异是历史去重口径：脚本当前输出 `live_budget_rows=98`，但去重触发事件为 `49`，说明 native live 与相关事件记录存在成对或重复日志表达；研究判断采用去重事件和窗口交叉核对，不把重复行当成新增事件。

## 16. 研究判断

建议状态：`observe`

理由：7Z32 支持 A22 维持默认关闭观察，但不支持生产 promote。A22 的历史优势仍有研究价值，工程边界也干净；不过 post-design 真实触发为 0，继续滚动无触发短窗不会产生收益证据，只会重复“工程通过但无触发”的结论。

## 17. 下一步

下一轮不再新开 A22 无触发短窗。只有出现以下任一条件，才重启 A22 收益门禁：一是实盘系统 dry-run 或委托成交日志可读；二是新增 forward/OOS 日志中出现真实 A22 触发；三是平台数据出现足够外部样本并能形成事件级收益复核。否则 A22 维持 observe，默认策略继续 hard5。
