## 1. 新手摘要

这次实验想知道：三个顶刊方向（MAX/CS dispersion/GSADF）的错位一日负控都出现"原始效应为正、错位后变负"的反转，这是真信号不稳定，还是负控实现的数据窗口假象？
我们原本预计：错位反转主要是数据窗口限制（valid_count 仅 20-54/165-313），扩大窗口后应消失或大幅减弱。
实际看到：错位反转是**脚本 bug**，不是信号问题。`build_daily_lookup` 只查了 raw_top_qmt 的 41 个标的，但错位负控需要 hard5_first_qmt（baseline）的前向收益。no_base=298/361 个事件因 baseline 不在 lookup 中被丢弃，valid_count 仅 54，有严重选择偏差。修复后（codes 41→112）valid_count 54→307，shift_prev1 H10 从 -0.028(反转) 变 +0.017(不反转)，BL8Y passes_gate=True。
这说明：错位反转完全是数据查询范围 bug 导致的选择偏差假象，真信号日期对齐敏感性不存在。
但还不能说明：其他只读面板是否也有类似 baseline 查询遗漏（本次已修复三个脚本）。
下一步要做：CS dispersion 升级 promote_candidate，进入 formal。三个脚本的 fetch 修复已同步。

## 2. 研究背景

FZM4/BL8Y/UEAC 三个只读面板的错位一日负控（shift_prev1/shift_next1）出现完全一致的反转模式：
- 212 版：原始 H10 effect +0.034 → shift_prev1 -0.058 / shift_next1 -0.042（valid_count 20/165）
- BL8Y 361 版：原始 +0.015 → shift_prev1 -0.028 / shift_next1 -0.025（valid_count 54/313）

361 版 valid_count 从 20 升到 54（2.7x），反转幅度从 -0.058 减到 -0.028，说明部分是数据窗口问题，但即使扩大窗口仍反转。这是 CS dispersion 升级 formal 的唯一阻塞，也是影响所有后续只读面板可信度的方法论问题。

## 3. 实验前假设

一句话写清本次只验证什么：错位一日负控的反转主要由"错位日大量标的查不到前向收益导致 valid_count 过小且有选择偏差"造成，而非真信号日期对齐敏感性；用更长数据窗口（覆盖错位日的完整前向收益）重跑后，反转应消失或变为不显著。

## 4. 实验前预测

如果假设为真，应该看到：

- 指标：valid_count 从 54 升到接近 313（全体事件数），错位 effect 从 -0.028 变为接近原始 +0.015 或不显著。
- 交易行为：（只读诊断，无交易）
- 风险表现：不适用
- 分段表现：错位负控在各分段不再一致反转。

## 6. 竞争性解释

即使扩大窗口后反转消失，也可能是：

- 扩大窗口引入了新的选择偏差（能查到前向收益的错位日本身有特殊性）。
- 反转消失只是因为样本量增大后均值被稀释，不是真稳定。
- 错位负控框架本身不适合日频事件级信号（VZ8Q 设计用于 5 日热点，不是 20 日动量）。

即使扩大窗口后仍反转，也可能是：

- 真信号有强日期对齐敏感性（路径依赖），错位即破坏。
- 当前 hard5 事件级 effect 本身是日期对齐的伪相关。

## 7. 证伪条件

出现以下情况，本假设不通过：

- 扩大窗口后 valid_count 仍远低于全体事件数（说明数据窗口不是主因）。
- 扩大窗口后反转仍显著（说明真信号有日期对齐敏感性）。
- 扩大窗口后 effect 变为不显著而非接近原始（说明原始效应本身不可靠）。
