## 1. 新手摘要（这条实验在说什么）

> ⚠️ **本实验推翻了 EX-8XXB 的诊断方向，并修正了主控本轮早些时候的错误结论。** 真正的 bug 不是"fallback 用估算值污染广度"，而是 `_r010a_raw_closes` 这个缓存用了 `dict.update()` 跨日累加、永不清空，导致每个 ETF 的价格序列**冻结在它最后一次出现的那个交易日**。长周期（十一年）回测里累积的冻结序列远多于、且冻结日远早于单段回测，于是同一天算出的中位 20 日收益符号都可能相反。

**一句话：代码里有个缓存叫 raw_closes，它本该每天刷新，却写成了"只增不减、永不重建"，把几年前停更的 ETF 价格序列留到今天当"最近20天"用，导致十一年长回测的市场状态判断失真。**

## 2. 一组铁证：2024-06-25 单段 vs 十一年

连"涨还是跌"都算反了，说明进入中位数计算的 `ret20_list` 样本集合在两段回测里内容完全不同。

## 3. 根因链（代码级，主控逐行复核）

### 3.1 raw_closes 用 update 累加，永不重建（病根）

`_score_etfs_batch`（def@7781）第 7805-7807 行：

```python
7805  if not hasattr(context, '_r010a_raw_closes'):
7806      context._r010a_state_prices = {}        # 仅首次创建
7807  context._r010a_raw_closes.update(raw_closes_cache)   # update 累加，非替换
```

- `raw_closes_cache`（7792-7802）只包含**当日通过 MA 过滤（passed_ma）的 ETF**，序列是相对当前日的滚动窗口，**末尾停在 T-1**。
- `dict.update()` 的语义：当日出现的 ETF 覆盖其值；**当日未出现的 ETF 保留旧值，冻结在它最后一次出现的那个交易日的 T-1**。
- 这个 dict **整个回测周期内永不清空、永不整体重建**，单调累加每一个曾经通过 MA 的 ETF。

### 3.2 对比：state_prices 是每日重建的（健康的对照组）

`_refresh_state_price_cache`（def@7439）第 7443-7457 行：

```python
7445  cache = {}                       # 全新字典
7446  for etf in etf_pool:             # 当日 combined_pool 全员
7451      closes = pd.to_numeric(...).dropna().values
7455      closes = np.append(closes, current_price)   # 末尾拼 T 日价
7457  context._r010a_state_prices = cache    # 整体赋值，非 update
```

state_prices 每个回测日**全新字典 + 整体替换**，末尾停在 T，是正确的滚动窗口。**state_prices 不是污染源。**

### 3.3 两个"兼容旧缓存"合并块把冻结序列注入 state_prices（污染入口）

- 合并点 #1：`_build_offense_soft_rank_gate_signals`（def@682）第 685-689 行。
- 合并点 #2：`_record_market_state_from_scores`（def@2176）第 2191-2196 行。

两处逻辑相同：

```python
raw_closes = getattr(context, '_r010a_raw_closes', {})
if isinstance(raw_closes, dict):
    for etf, closes in raw_closes.items():
        if etf not in state_prices:
            state_prices[etf] = closes      # 注入冻结序列
```

随后 `_calc_etf_state_metrics` 对**合并后的 state_prices** 全量计算，再取 `np.median(ret20_list)`。

### 3.4 _calc_etf_state_metrics 的 ret20 只看末尾两点，不带日期校验（放大器）

`_calc_etf_state_metrics`（def@2332）→ `_safe_ret`（def@2366）：

```python
2367  if len(arr) <= days or arr[-days - 1] <= 0:
2368      return 0.0
2369  return float(arr[-1] / arr[-days - 1] - 1.0)   # ret20 = arr[-1]/arr[-21]-1
```

ret20 完全由序列末尾两个点决定。它**没有任何日期校验**——传入冻结在 2018 年的序列，算出来的就是 2018 年某日的 20 日收益，而非 2024-06-25 的。

### 3.5 为什么十一年 vs 单段在 2024-06-25 算出符号相反

1. state_prices 当日只覆盖 combined_pool 里 `len(closes)>=21` 且 key 能匹配的 ETF；新上市<21 日或代码不匹配的 ETF 在 state_prices 里**缺席**。
2. raw_closes 因 update 累加 + 永不清空，对每个缺席的 ETF 都有历史残留可注入：
   - **十一年回测**：到 2024-06-25 已累积 ~9.5 年里所有曾通过 MA 的 ETF（含已退出当前池的动态成员、已退市/换码标的）。合并时大量**冻结在 2015–2024 各历史日期**的序列被注入，各自的 ret20 算的是冻结日的 20 日收益，与 2024-06-25 无关，拉偏中位数。
   - **单段（2024）回测**：raw_closes 从 2024-01-01 起空，到 2024-06-25 只累积上半年曾通过 MA 的 ETF，集合小、冻结日都近（2024 年 1–6 月）。注入的陈旧样本少且新 → ret20 分布不同 → median_ret 落到另一侧。
3. `pool_size=215` 是 combined_pool 常量，**不是 ret20 有效样本数**。两段真正进入 median_ret 的样本集合（数量 + 各自冻结日期）完全不同，这个差异被 pool_size 这个常量掩盖了。

## 4. 为什么 EX-8XXB 的诊断方向错了

### 4.1 fallback 污染论不成立

EX-8XXB 认为"fallback 用 `annual_ret*(20/250)` 估算 ret20 污染广度"。但 2024-06-25 的铁证显示：pool_size=215 >> fallback 阈值 10，**fallback 根本不触发**。广度 0.5746/0.3469 都是真实计算值，与 fallback 无关。

### 4.2 "CH 真实 0.345"是概念混淆

EX-8XXB 把 0.345（CH 全市场**上涨家数占比**）当作 ret20_breadth 的基准。但 ret20_breadth 的定义（第 2255-2257 行）是"ETF 候选池里 20 日正收益 ETF 占比"——这是 ETF 池截面指标，与全市场上涨家数是**两个不同指标**，不应直接相等。0.5746（2024 牛市里 57% 的 ETF 20 日正收益）在牛市完全可能是真实的。

### 4.3 EX-8XXB "修复后广度回落 0.347"是巧合，不是修复效果

EX-8XXB 修了第 717 行 fallback，然后重跑单段 2024 看到广度 0.347，宣称"修复生效"。但单段 2024 因 raw_closes 累积少、注入的陈旧样本少，广度本就接近"单段自身口径"的值。这个 0.347 是单段自身特征，不是 717 修复带来的——把因果搞反了。

## 5. 主控本轮早些时候的错误（已纠正）

主控在 2026-06-28 上午误信 EX-8XXB 的 fallback 论，补修了第 2229 行同名 fallback（ret20=NaN，无 append）。补修后重跑 decade4_fixed，发现：

- ✅ 权益确实从 47x 变成 15x（行为变了）——一度以为修复生效；
- ❌ 但 2024-06-25 广度纹丝不动（0.5746→0.5746）——证明没对症；
- ❌ 连单段/十一年都不走 fallback 的这天，广度仍不同——证明根因不在 fallback。

主控随即判断"2229 修复没对症、且有副作用（15x 是改坏值）"，已**回退 2229 修复、停掉 decade4_fixed**。回退后 py_compile 通过，代码恢复原样。

**教训**：补修前没有先用铁证确认"修复点确实是当天的执行路径"。2024-06-25 pool_size=215 远超阈值，本可一眼看出 fallback 不触发，却先动手改代码——这是过早行动。

## 10. 修复版结果定论（2026-06-28，本实验的核心交付）

| 年份 | baseline | RA5 | A2 | 关键事件 |

| 2015 股灾 | 48.9 | **69.5⭐** | 48.9 | RA5 防御股灾仍有效(+20.6pp)；A2 零防御(机制盲区仍在) |
| 2018 贸易战 | 13.0 | **-3.7⬇** | 2.7 | RA5 反而亏损(过度防御) |
| 2023 震荡 | 20.6 | **4.1⬇** | 21.1 | RA5 落后 16.5pp(频繁误切) |
| 2024 大跌+924 | 69.6 | **101.4⭐** | 101.5 | RA5/A2 都吃到大跌转防御+抄底(修复版才暴露 2024 是发力段) |
| 2025 牛市 | 73.6 | **58.2⬇** | 73.4 | RA5 牛市误伤落后 15.4pp；A2 几乎不伤 |

**机制定论**：
- **A2 是稳健最优**：各年收益几乎贴合 baseline（差<1.5pp），只在真正发力段（2024 +32pp）正贡献，且 MDD 全程改善（-31.91→-27.03）。对污染免疫使其结论可信。
- **RA5 是"激进降回撤但牺牲收益"方案**：只在真崩盘段（2015/2024）有效，在震荡/慢牛/牛市段（2018/2023/2025）反复误伤。修复后净收益落后 baseline -13.6%，但 MDD -20.79% 是三段最好。适合"宁要低回撤不要高收益"的偏好，不适合作为收益型主选。
- **bug 版为何 RA5 显得最优**：bug 把市场伪装成持续 unfavorable(74%)，恰好压制了 RA5 的过敏反应，让它行为接近 baseline 又在某些段吃到防御红利 → 虚假的 47.50x。**这不是 RA5 真实强，而是 bug 恰好抵消了它的弱点。**

### 10.6 对 EX-HUWV 叙事的彻底推翻

EX-HUWV 的核心论点是"4 段空仓重置假象"——它认为单段 vs 十一年的收益差异主因是"4 段空仓重置高估防御效果"。但 HUWV 所依据的十一年回测（decade2）本身被 raw_closes bug 污染，其所有结论建立在错误数据上：

| HUWV 的结论（基于 bug 版 decade2）| 修复版真相（decade5_fixed）| 判定 |
| --- | --- | --- |
| RA5 47.50x 全周期最优，超额主要来自 2015 | RA5 31.43x **落后** baseline -13.6%，三段最低 | **推翻** |
| A2 39.43x 落后 RA5 -16.9%，不应升级 | A2 39.38x **超** baseline +8.2%，**全周期最优** | **推翻** |
| A2 有 2015 牛顶崩盘零防御的"致命盲区" | 盲区机制仍在（2015 A2=baseline），但十一年里未让 A2 输（baseline 2015 本就涨 48.9%） | 机制观察成立，但"致命"定性过重 |
| 4 段空仓重置系统性高估防御效果 | 此方法论**可能有独立价值**，但 HUWV 用 bug 数据做的单段 vs 十一年对比无法证明——主因是 bug 不是空仓重置 | **待修复版单段 vs 十一年对比重新验证** |

**HUWV 的"4 段假象"叙事本身是 bug 制造的二次假象**：HUWV 看到"RA5 在十一年里仍最优"，于是构造"空仓重置高估防御"来解释单段 vs 十一年差异；但 RA5 在十一年里"最优"本就是 bug 的产物。修复后 RA5 反而最差，HUWV 的解释框架整个失去立足点。

### 10.7 对 DEC 的修订方向（路线级，主控定论）

#### DEC-K7R9（RA5 promote_candidate）→ 降级为 observe / 风险偏好可选

- 第 9 节补注（基于 HUWV）"RA5 仍是十一年最优 47.50x"**作废**。
- RA5 修复后十一年 31.43x **落后** baseline -13.6%，不再是"全周期最优"，promote_candidate **不成立**。
- RA5 真实定位：**激进降回撤（MDD -20.79% 三段最好）但牺牲收益**的方案，降为"低回撤偏好可选组件 / observe"，不作为收益型主选，不进入 shadow 主线。
- 三维门控机制本身在真崩盘段（2015/2024）有效，但震荡段误伤使其净收益为负。

#### DEC-DTH2（A2 升级）→ 重新确认 A2 为最优（方向回归原始决策）

- 第 11 节修订（基于 HUWV 推翻 A2）**作废**。
- 修复版证明 A2(39.38x) **确实优于** RA5(31.43x) 和 baseline(36.38x)，原始决策"A2 升级"的方向是对的——只是当时（4 段 bug 版 + 十一年 bug 版）无法用干净数据证明。
- 状态从 `superseded_by_long_cycle` 改回 `promote_candidate`（A2 为下限空仓路线最优候选）。
- **保留的 caveat**：A2 在 2015 类"牛市顶崩盘"零防御的机制盲区客观存在（ma200 斜率在牛顶仍正），十一年里未让 A2 输（因 baseline 本身涨了），但未来若再遇类似行情需警惕。这不妨碍 A2 作为当前最优候选。

#### 诚实记录：这是结论的第三次反转

| 阶段 | 数据基础 | 结论 | 状态 |
| --- | --- | --- | --- |
| 第1次（DEC-DTH2 原始）| 4 段 bug 版 | A2 超 RA5 +9.9%，升级 | 方向对，数据脏 |
| 第2次（HUWV + DEC 修订）| 十一年 bug 版 | RA5 最优，A2 落后，superseded | 数据脏，结论错 |

**教训**：前两次反转都建立在被同一 bug 污染的数据上（4 段轻度污染、十一年重度污染），导致结论反复横跳。**根因不在策略本身，而在基础设施（缓存 bug）。** 本节用 median_ret 铁证 + confirmed_state 分布铁证 + 收益三段对比锚定，结论可信度与前两次有本质区别。**未来任何"RA5 vs A2"的结论，必须先确认 raw_closes 已修复（代码 7810 行）+ 复核当日 median_ret 三段一致。**
