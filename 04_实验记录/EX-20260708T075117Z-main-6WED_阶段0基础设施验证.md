## 1. 新手摘要

这次实验想知道：聚宽官方 jqdatasdk 纯 API 直连，能不能在合理时间内拉完所有历史数据，作为阶段1（把数据库从 xtdata 口径切回聚宽口径）的基础设施。

我们原本预计：全量工期不超过 7 天，配额占比低于 5%，单次延迟日线 < 2 秒、分钟线 < 3 秒。

实际看到：日线延迟 0.147 秒、分钟线延迟 0.196 秒、全量工期 1.7 天、配额占比 0.47%、28 个单元测试全通过。三项主门槛全部达标。

这说明：当时的阶段0已经证明聚宽纯 API 历史拉取在工期和配额上可行。该旧 `jq_fetcher` 后续已被 V2 的 `src/quant_n3/jq_fetcher/` 与 jq_v3 更新链路取代。

但还不能说明：切回聚宽口径后策略复现数字会不会真的向聚宽官方靠拢（那是阶段1要回答的）。

当前状态：阶段1及后续 V2 数据链路建设已经完成；本实验不再承担待执行任务。后续完整性、导入和恢复工作以当前平台 `docs/jq-v3-data-import-contract.md` 与 `docs/jq-v3-project-manual.md` 为准。

## 2. 研究背景

本实验属于 [[02_研究方向/RD-20260708T075106Z-main-3MHU_聚宽数据库全面重构|聚宽数据库全面重构]] 的历史阶段0。背景是当时旧平台（现归档为 V1.4）13 张主表存在口径错配（表名 jq_*、配置 provider=jq，但实际是 xtdata 口径），导致 valuation 的 PE/PB/PS 全空、stock_info 行业全 None、复权因子与聚宽不等价。在切口径之前，必须先验证 jqdatasdk 纯 API 直连这条路走得通。

## 3. 实验前假设

jqdatasdk 纯 API 直连可在合理时间（<=7 天）内完成 13 表全量历史拉取，配额充足，可作为阶段1的基础设施。

## 4. 实验前预测

如果假设为真，应该看到：

- 工期：全量历史拉取 <= 7 天（门槛）。
- 配额：占配额比 < 5%。
- 延迟：单次日线查询 < 2 秒，单次分钟线查询 < 3 秒。
- 稳定性：认证成功、断点续传可恢复、重试机制能扛住偶发失败。

## 6. 竞争性解释

即使工期和配额达标，也可能存在隐藏风险：

- 加速比不达标时，可能是 jqdatasdk 服务端速率限制过严（需要回退到混合方案：离线导出补量分钟线）。
- 配额看似充足，但分钟线全量尚未实跑，实际行数可能远超样本估算。
- 延迟达标可能是样本标的（50 只）特殊，全标的（7047 只）规模下可能劣化。

## 7. 证伪条件

出现以下情况，本假设不通过：

- 全量工期 > 7 天。
- 配额不足（占配额比 > 50%，即一次全量就吃掉一半以上配额）。
- jqdatasdk 无法认证或无法拉取（框架不可用）。

## 13. 支持证据

- benchmark 报告 `${LEGACY_QUANT_PLATFORM_ROOT}/tmp/jq_speed_benchmark_report.txt`（速率报告，含各项延迟/加速比/工期/配额）。

- checkpoint 原子写 + 损坏备份测试（`test_load_handles_corrupt_json` 通过，证明断点续传可扛损坏）。
- 认证成功，配额剩余 199,894,549 / 总 200,000,000。

## 14. 反对证据

- 并发加速比 1.27x 未达 3.0x 门槛。但经核实是**聚宽服务端按账号串行化**（不是脚本 bug，不是本地线程或 GIL 问题），且由于单次延迟足够低，工期仍远低于门槛（1.7 天 << 7 天），加速比未达标与工期门槛解耦，不构成阻塞。

## 15. 偏差诊断

实验前预测和实际结果的不一致：

- **工期、延迟、配额三项**：完全一致，且实际值远优于门槛（不是勉强达标，而是大幅富余）。
- **并发加速比**：预测 3.0x，实际 1.27x，**不一致**。原因：聚宽服务端对单账号做请求串行化，多线程并发在服务端被排队。这不是本地实现缺陷，增加线程数无法改善。但因其与工期门槛解耦（单次延迟低 → 即便串行，总工期仍 1.7 天），所以不构成对"纯 API 直连可行"假设的证伪。

## 16. 研究判断

建议状态：`completed`（阶段0基础设施验证完成，不升级为策略 promote）。

理由：本次是基础设施验证，三项核心门槛（工期 1.7 天、延迟远低于门槛、配额占比 0.47%）全部达标，28 个单元测试通过，断点续传可扛损坏。唯一未达标的并发加速比经核实为聚宽服务端串行化（非 bug），且与工期解耦。jq_fetcher 框架具备认证、断点续传、重试、配额监控、并发拉取能力，可作为阶段1的基础设施。本项不释放任何策略 promote。
