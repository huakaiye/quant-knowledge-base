## 1. 新手摘要

这次实验想知道：  
G7S8 产出的 dry-run `orders.csv` 能否和 A22/KFSQ 这类候选信号表做只读关联，形成后续外部观察的事件索引。
我们原本预计：  
可以做一个通用关联门禁：支持标的级信号和组合级日期信号，按订单日期和可选标的匹配，输出匹配、未匹配和信号汇总。
实际看到：  
脚本、单测和样例关联均已完成。样例 A22 标的级信号与样例订单形成 `symbol_date` 匹配，样例 KFSQ 组合级信号与样例订单形成 `date_only` 匹配；真实 A22 7Z32 格式源和真实 KFSQ scored panel 格式源接入后均没有误匹配 2026-06-19 样例订单。
这说明：  
未来真实 dry-run 订单出现后，可以用 48VR 把订单分成“与候选信号有关”和“无候选信号关联”两类，再决定是否进入外部观察验证。
但还不能说明：  
即使订单与候选信号匹配，也不能说明交易收益有效，更不能说明可以改实盘。
下一步要做：  
等待真实 QMT dry-run JSON；跑完 G7S8 后，用 48VR 同时关联 A22 7Z32 触发表和 KFSQ scored/forward 面板。

## 2. 研究背景

本实验属于 [[02_研究方向/RD-20260618T105950Z-main-7FY3_双池轮动真实交易微观数据低滞后研究|7FY3]]。B5JS 已经能生成 dry-run JSON，G7S8 已经能把 JSON 拆成 `orders.csv` 和门禁结果，但“订单是否对应 KFSQ/A22 候选触发”仍需要手工判断。

如果没有订单-信号关联层，真实 dry-run 到来后仍不能直接回答：这笔订单是在 A22 触发日附近，还是在 KFSQ 的高风险状态附近，还是与候选信号无关。因此 48VR 先建设只读关联门禁。

## 3. 实验前假设

如果 dry-run 订单与候选信号关联门禁可用，则它应能读取 G7S8 `orders.csv` 和可配置信号 CSV，按日期窗口与可选标的生成匹配表、未匹配订单和信号源汇总。

## 4. 实验前预测

如果假设为真，应该看到：

- 指标：脚本单测通过；样例订单与 A22 样例信号能标的级匹配；样例订单与 KFSQ 样例信号能日期级匹配；不匹配信号不会误报。
- 交易行为：不连接 QMT、不提交委托、不访问数据库、不运行回测；只读 CSV。
- 风险表现：标的级信号要求 symbol 一致；组合级信号允许只按日期匹配；输出必须保留 unmatched orders。
- 分段表现：本次不评估收益、回撤、胜率或分段 alpha。

## 6. 竞争性解释

即使结果符合预期，也可能是：

- 样例订单来自合成 JSON，不是真实 QMT dry-run。
- A22 当前 post-design 真实触发为 0；历史触发匹配不等于现在可交易。
- KFSQ 是组合状态信号，日期匹配只能说明同日关联，不能说明订单由该信号驱动。

## 7. 证伪条件

出现以下情况，本假设不通过：

- 标的级信号在 symbol 不一致时仍被匹配。
- 无订单或无信号时仍宣称可观察。
- 输出没有 unmatched orders，导致无法看见无关联订单。
- 脚本需要连接 QMT、数据库或回测才可运行。
