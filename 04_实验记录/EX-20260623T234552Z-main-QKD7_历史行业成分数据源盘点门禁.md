## 1. 新手摘要

这次实验想知道：当前平台里到底有没有可直接拿来做“行业轮动后再选行业内个股”的历史行业成分数据。
我们原本预计：可能有聚宽或申万行业字段、801 行业指数成分，或者平台文件里已有导出的行业成分表。
实际看到：`jq_stock_info` 和备份表的 `sw_l1/sw_l2/sw_l3/jq_l1/jq_l2/zjw` 全部 0 覆盖；`index_constituent` 有 918043 行，但没有 801 开头行业指数成分；`jq_bar_daily` 也没有 801 行业指数行情；文件扫描没有疑似可用源数据文件。
这说明：当前平台只有行业 API 文档参考，没有可回测的本地历史行业成分数据。
但还不能说明：行业内个股增强这个想法无效，只能说明现在不能直接实现和回测。
下一步要做：暂停个股增强实现；若继续，先预注册历史行业成分导入方案，再重新做数据门禁。

## 2. 研究背景

这个实验属于 [[02_研究方向/RD-20260623T125116Z-main-DVXD_双池轮动行业状态机与个股增强模块|双池轮动行业状态机与个股增强模块]]。2GV8 已经暂停 ETF 代理池 `final_top` 路线，研究自然回到原始问题：如果要从行业选到行业内个股，必须先有可审计的历史行业成分或行业映射。

## 3. 实验前假设

如果平台已有历史行业成分或可用行业映射，则可以继续设计行业状态机加行业内个股增强的最小只读面板。

## 6. 竞争性解释

即使结果显示本地无源，也可能是：

- 数据存在于未被当前脚本扫描到的外部目录或未接入 ClickHouse 的私有文件。

- `index_constituent` 只收录宽基指数成分，未覆盖申万 801 行业指数。

- `index_constituent` 和 `jq_bar_daily` 均没有 801 开头行业指数/成分数据。
- 文件扫描没有疑似可用的行业成分源数据文件。

实际触发全部证伪条件。

## 13. 支持证据

- `summary.json` 显示 `static_stock_industry_field_gate=false`、`index_801_history_gate=false`、`file_based_industry_source_gate=false`、`local_historical_industry_source_gate=false`。
- `jq_stock_info` 5509 只股票与 `jq_stock_info_backup_dates_20260515` 5505 只股票的行业字段非空数均为 0。
- `index_constituent` 总行数 918043，但 `index_constituent_801` 行数为 0。
- 数据字典存在 `get_industry_stocks`、`get_industries` 等 API 说明，并注明当前没有行业及概念行情数据；这说明有外部 API 入口，但本地没有可回测历史快照。

## 14. 反对证据

- `index_constituent` 有宽基指数成分，说明平台具备指数成分表结构；如果后续导入 801 成分，技术上可承接。
- 聚宽 API 文档提供行业成分获取方法，后续可能通过合法数据更新或离线导入补齐。

## 15. 偏差诊断

实验前预计可能能从备份表或文件中找到行业成分，但实际所有本地门禁均失败。差异原因更像是平台从未持久化行业成分数据，而不是字段命名没找到；因为脚本同时检查了表名、列名、静态字段、801 成分、801 行情和平台文件名。

## 16. 研究判断

建议状态：`park`

理由：当前没有本地历史行业成分数据，不能进入行业内个股增强的只读面板或回测实现。继续实现会把行业归属问题变成手工映射或事后成分，未来函数风险不可控。
