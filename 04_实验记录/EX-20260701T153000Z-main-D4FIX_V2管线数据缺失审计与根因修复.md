## 对新手的短总结

数据库曾经有多处数据缺失和重复，根因是当前用的 V2 数据更新管线是一个"精简版"，砍掉了自动修复、派生表同步和完整性检查三大功能，加上写入脚本有个"出错继续写"的 bug 导致重复。我们已经：(1) 修复了所有已发现的缺失和重复；(2) 给 V2 管线加回了完整性门禁和派生表同步；(3) 把基金标的纳入了日常同步范围；(4) 修复了涨跌停价因聚宽导出日期写死而停滞的问题。下次 V2 运行时会自动做完整性检查和派生同步。

## 关键教训

1. **ReplacingMergeTree 的去重是异步的**——写入层必须自己做"删后插"，不能依赖引擎去重。v2 表不重复是因为走了 safe_replace（删后插），real 表重复是因为 DELETE 失败被吞。
2. **分批补数不能用 replace 模式**——按日期 DELETE 会误删整个日期的其他批次数据。必须合并成一个大文件再一次性 replace，或用 append+去重。
3. **完整性门禁必须检查 bar 数和时段覆盖**——只判"有日线无分钟线"的存在性检测无法发现半日缺口（上午有下午无）。
4. **聚宽数据导出的日期不能硬编码**——到点就停，且无告警。
5. **日线也需标的数骤降门禁**——05-28 沪市全缺(2235 vs 正常7200)只在日线层可见，分钟线门禁无法发现。门禁必须覆盖日线+分钟线两层。
6. **标的符号冲突需用 exchange 区分**——000001.SH(上证指数)和000001.SZ(平安银行)的 symbol 相同，历史导入混入导致重复键。GROUP BY 查重必须含 exchange 列，否则误报。

### 发现两条桌面入口
| 桌面快捷方式 | 调用链 | 管线 |
|---|---|---|
| **数据更新.lnk**（用户主用） | V2/一键更新数据_V2.cmd → xtdata_daily_gui.py → xtdata_daily_v2.py --days 5 | **V2**（含全部修复）✅ |
| 更新量化数据.lnk | 更新量化数据.cmd → run_standalone_data_update.ps1 → standalone_data_update.py | **standalone**（独立编排） |

### standalone 的独立缺陷
standalone 是与 V2 平行的第二条写入通道（有韧性下载+并发锁，但**完全不复用 V2 代码**）：
- 写入安全（V1 safe_replace_stage + 备份回滚 + OPTIMIZE FINAL）已与 V2 持平
- 但**缺门禁、缺派生、缺涨跌停**——之前修复的三个保障阶段只在 V2 里

### standalone 移植修复
在 `standalone_data_update.py:main()` 的 `run_extra_tables` 后新增 `run_post_update_stages()`，调用 V2 的三个 WSL 脚本：
1. `tushare_limits.py`（涨跌停补齐，修复 limit_up 永空）
2. `derive_tables.py`（派生 adjust_factor/st_full/limit_full/trade_status）
3. `minute_integrity_gate.py`（14 项完整性门禁）

### 结论
**两条桌面入口现在都有完整保护。** 无论用户用"数据更新"（V2）还是"更新量化数据"（standalone），都会执行门禁+派生+涨跌停。
