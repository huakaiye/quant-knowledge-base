# 路线图维护规范

Markdown Mermaid 图不适合承载长期增长的全局路线图。节点变多后，Obsidian 预览区无法方便缩放，阅读体验会迅速变差。

本库采用“Canvas 看全局，Markdown 讲规则，台账做检索”的路线图方案。

## 推荐工具分工

| 工具 | 用途 | 节点规模 |
| --- | --- | --- |
| Obsidian Canvas | 全局路线、方向关系、关键决策路径 | 10 个以上节点 |
| Markdown Mermaid | 小型缩略图、局部流程示意 | 10 个以内节点 |
| 台账 CSV | 精确检索、状态、路径、ID | 不限 |
| 方向页 | 解释研究信念、证据和下一步 | 单方向 |
| 决策卡 | 解释为什么改变路线 | 单决策 |

## 全局 Canvas 规则

全局 Canvas 路径：

```text
00_入口/研究路线图.canvas
```

全局 Canvas 只放：

- 研究驾驶舱。
- 策略级研究方向。
- 模块级研究方向。
- 当前关键实验。
- 当前关键决策。
- 必要的方法论入口。

不要把每一次参数扫描、每一个结果文件、每一个文献卡都塞进全局 Canvas。那会让图重新失控。

## 分层拆图规则

满足任一条件时，应新建子 Canvas：

- 单个策略方向超过 20 个实验节点。
- 单个模块方向超过 10 个实验节点。
- 全局 Canvas 中同一块区域需要缩放到很大才能读清。
- 某条路线已经有多个分叉，例如进攻、防御、执行各自持续演化。

子 Canvas 推荐命名：

```text
02_研究方向/<rd_id>_路线图.canvas
```

全局 Canvas 中只保留该子 Canvas 的入口节点。

## 节点粒度

| 层级 | 全局 Canvas 是否展示 | 说明 |
| --- | --- | --- |
| 策略级方向 | 展示 | 全局主干 |
| 模块级方向 | 展示 | 策略下的主要分叉 |
| 关键决策 | 展示 | 改变路线或状态的节点 |
| 当前关键实验 | 展示 | 当前正在推进或刚影响方向的实验 |
| 普通实验 | 不展示 | 放实验台账和子 Canvas |
| 文献和因子灵感 | 通常不展示 | 只有变成关键假设时才展示 |
| 平台结果目录 | 不展示 | 放策略档案和实验记录 |

## Canvas 连线方向规则

Canvas 边必须遵守层级单向流动，禁止跨层级倒连，避免图变成无法阅读的网状结构。

### 合法层级与流向

```text
META（驾驶舱/规范） → 策略级方向 → 模块级方向 → 实验 → 决策
                                                    ↑
                                              文献/灵感（来源）
```

### 边方向规则

| 边类型 | 允许方向 | 说明 |
| --- | --- | --- |
| `parent` | 子方向 → 父方向 | RD 归属 |
| `experiment_of` | 实验 → 方向 | EX 属于哪个 RD |
| `decision_affects` | 决策 → 方向 | DEC 影响哪些 RD |
| `decision_on_experiment` | 决策 → 实验 | DEC 基于哪个 EX |
| `produced_decision` | 实验 → 决策 | EX 产生了哪个 DEC |
| `lit_source` / `idea_source` | 实验 → 文献/灵感 | EX 的来源 |
| `来源文献` | 文献 → 方向 | 顶刊驱动新方向 |

### 禁止的连线

- **实验/决策直连策略父方向**：如 `EX → DP00`、`DEC → DP00`。实验只连到所属模块方向。
- **决策回流到模块/实验作为下一轮起点**：如果决策触发新方向，应在子 Canvas 里画 `新方向 RD → 旧决策`（方向指向决策来源），而非 `旧决策 → 新方向`。
- **文献边方向不一致**：同一张图里文献节点连出方向必须统一（LIT → MODULE），不能部分反向。
- **同方向文献连成环**：文献是叶子节点，不应有边连回实验或决策。

### group 分组

全局 Canvas 和子 Canvas 都应使用 group 节点包裹同一分支的节点，例如"score-cap 主线"、"防御模块"、"动态资金热度"。平铺无分组的图在节点超过 15 个后无法阅读。

### 与知识图谱的关系

Canvas 是人类导航视图，`tools/Build-ResearchGraph.ps1` 生成的 `研究图谱.json` 是机器可读的完整引用图。两者数据来源相同（frontmatter 引用关系），但 Canvas 只展示关键路径，知识图谱展示全部节点和边。Canvas 连线违规时，知识图谱仍能正确反映结构化引用。

## 维护流程

新增方向或关键决策后：

1. 更新对应正文。
2. 更新 `01_台账/`。
3. 更新 `00_入口/研究驾驶舱.md`。
4. 更新 `00_入口/研究路线图.canvas` 或对应子 Canvas。
5. 若节点太多，拆分子 Canvas，而不是继续压缩全局图。

## 给 Agent 的要求

- 不要把 Canvas 当唯一事实源。
- Canvas 节点必须能链接到正文文件。
- 大图只表达路线关系，不承载完整实验结论。
- 结论仍以实验记录、决策卡和台账为准。
