# 平台协作规范

当前回测平台已经统一为 V2.0。研究库只登记平台资产和研究证据，不保存策略代码、大型结果或数据。

## 三个逻辑根

```text
${QUANT_PLATFORM_ROOT}
${LEGACY_QUANT_PLATFORM_ROOT}
${LIVE_TRADING_ROOT}
```

| 逻辑根 | 当前含义 | 是否可执行新实验 |
| --- | --- | --- |
| `${QUANT_PLATFORM_ROOT}` | V2.0 当前平台；默认 `E:\量化平台_V2.0`，WSL 为 `/mnt/e/量化平台_V2.0` | 是 |
| `${LEGACY_QUANT_PLATFORM_ROOT}` | V1.4 旧代码、旧配置和旧结果的只读证据根 | 否 |
| `${LIVE_TRADING_ROOT}` | 本机实盘系统根 | 仅按实盘规范 |

解析路径：

```powershell
pwsh -NoProfile -File tools/Get-QuantPlatformRoot.ps1 -Target Platform -Format All
pwsh -NoProfile -File tools/Get-QuantPlatformRoot.ps1 -Target LegacyPlatform -Format All
pwsh -NoProfile -File tools/Get-QuantPlatformRoot.ps1 -Target Live -Format All
```

本机路径通过环境变量或 `.research.local.json` 配置。共享文档不得写死个人路径。

## 路径可移植规则

| 资产状态 | 写法 | 说明 |
| --- | --- | --- |
| V2 当前资产 | `${QUANT_PLATFORM_ROOT}/<已核实相对路径>` | 路径必须真实存在，入口必须符合 V2 平台规范 |
| V1.4 历史资产 | `${LEGACY_QUANT_PLATFORM_ROOT}/<历史相对路径>` | 只读证据，不得用于启动新实验 |
| 原始历史记录 | 当时的绝对路径 | 可原样保留，但必须能从上下文识别为历史证据 |
| 实盘资产 | `${LIVE_TRADING_ROOT}/<相对路径>` | 不得包含账号、Token 或券商私密配置 |

禁止把 V1.4 路径的根目录机械替换为 `${QUANT_PLATFORM_ROOT}`。只有代码、配置、结果契约和受控入口都已迁入 V2 并通过门禁后，才能登记为 V2 当前资产。

平台迁移状态和策略资产边界见 [[00_入口/平台迁移状态|平台迁移状态]]。

## 职责边界

| 内容 | 放研究库 | 放平台 |
| --- | --- | --- |
| 研究方向、假设、实验解释、决策 | 是 | 否 |
| 文献卡、因子灵感、术语 | 是 | 否 |
| 策略代码、数据导入、运行内核 | 否 | 是 |
| 回测配置 | 只登记真实路径和摘要 | 是 |
| 回测结果、交易明细、大型 CSV | 只登记摘要和路径 | 是 |
| 质量门禁报告 | 登记结论和路径 | 是 |

## V2 运行边界

1. 回测平台必须在 WSL2 中运行，项目路径由 `Get-QuantPlatformRoot.ps1` 解析。
2. 进入 V2 后先阅读平台根目录 `AGENTS.md`。
3. Python、pytest、回测 CLI、性能分析和 NautilusTrader 命令统一使用 `.venv/bin/python`。
4. 每个策略必须使用平台公开的受控入口，不得直接调用内部函数、隐藏参数或旧通用 runner。
5. 五福只能通过 `.venv/bin/python scripts/run_wufu_v52.py ...` 启动。
6. 不得使用 V1.4 的 `src/run_v2_backtest.py`、`scripts/research/run_parallel_backtest.sh` 或 `python3` 裸环境启动当前实验。
7. 当前并发硬上限为 4 个受控任务；每个任务必须取得平台资源租约，并接受 RSS 上限和进程组清理。

通用命令形态：

```powershell
$platformWsl = pwsh -NoProfile -File tools/Get-QuantPlatformRoot.ps1 -Target Platform -Format WSL
wsl.exe bash -lc "cd '$platformWsl' && .venv/bin/python scripts/<策略受控入口>.py <参数>"
```

五福示例：

```powershell
wsl.exe bash -lc "cd '$platformWsl' && PYTHONUNBUFFERED=1 .venv/bin/python scripts/run_wufu_v52.py <参数> 2>&1 | tee <平台内日志路径>"
```

具体参数和结果位置以平台受控入口的 `--help`、平台文档和实际产物为准，研究库不得臆造统一的配置目录或结果目录。

## 尚未迁移的策略

若策略档案只登记 `${LEGACY_QUANT_PLATFORM_ROOT}`，或者仍提到 `src/strategies`、`configs/research`、`results/v2/research` 等 V1.4 资产，则该档案保存的是历史研究证据。处理顺序必须是：

```text
核对历史证据 -> 在 V2 建立原生策略资产 -> 建立受控入口 -> 通过数据与数值边界门禁 -> 重新回测 -> 更新研究库资产路径
```

迁移完成前不得：

- 回退运行 V1.4 产生新结论。
- 将旧结果写成 V2 复现结果。
- 因研究状态是 `active`、`observe` 或 `promote_candidate` 就推断平台资产已可执行。

## 可见进度与并发

- 单个回测使用 `PYTHONUNBUFFERED=1` 和 `tee` 或平台等效日志，保持阶段、错误和日志路径可见。
- 多段回测每段使用独立受控进程、独立日志和独立结果目录。
- 同时运行不超过 4 个任务；平台拒绝资源租约时必须降并发，不能绕过门禁。
- 超时只用于发现异常，不得把正常运行的回测结果当作超时失败；卡住时应核对 CPU、RSS、日志和进程组状态。
- 后台运行必须记录进程标识、日志路径、查看命令、停止方式和预计耗时。

可视化启动细则见 [[08_方法论/可视化分段回测规范|可视化分段回测规范]]。

## 禁止事项

- 不自动更新数据。
- 不无说明地使用过程不可见、无日志、无法监控的长回测命令。
- 不自动修改 MiniQMT 或实盘默认开关。
- 不把实盘账号、券商配置、Token、授权文件、客户端缓存或交易凭据写入研究库。
- 不把 shadow、observe、probe 标签升级为实盘信号。
- 不为追平结果而使用评分 override、交易 override 或后验行情修补。
- 不把平台结果文件复制进研究库。
- 不使用旧平台执行新实验。

## 实验记录中的平台字段

每份实验记录保留：

```yaml
platform_project: ${QUANT_PLATFORM_ROOT}
config_paths:
result_paths:
summary_paths:
quality_gate:
```

V2 当前资产必须填写实际存在的路径。历史资产使用 `${LEGACY_QUANT_PLATFORM_ROOT}` 并标明“历史只读证据”。没有运行的实验写 `未执行`，不得伪造结果。
