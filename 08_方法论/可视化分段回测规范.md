# 可视化分段回测规范

本规范描述如何在不绕过 V2 平台资源治理的前提下，让少量分段回测保持可见。当前并发硬上限为 4 个受控任务。

## 适用范围

- 跨年正式验证拆成自然年或稳定区间。
- 对照实验和少量变体需要分别观察日志。
- 一次最多同时启动 4 段。

大于 4 段的矩阵必须分批；平台资源租约可以进一步降低实际并发。并发量只影响调度，不得改变策略逻辑、数据口径或配置。

## 前置条件

1. 使用 `${QUANT_PLATFORM_ROOT}` 指向 V2 当前平台。
2. 在 WSL2 中运行。
3. 使用 `.venv/bin/python`。
4. 每段调用策略公开的 V2 受控入口。
5. 禁止 `--in-process`、直接调用内部函数、旧 `src/run_v2_backtest.py` 和旧 `run_parallel_backtest.sh`。

五福必须使用 `scripts/run_wufu_v52.py`。其他策略必须先在 V2 建立自己的受控入口，不能为了复用旧 config 回退到 V1.4。

## 分段规则

- 默认按自然年或策略定义的稳定区间拆分。
- 每段使用独立命令、独立进程、独立日志和独立结果目录。
- 每条命令的参数必须显式包含该段日期或配置，不得依赖共享可变状态。
- 启动前核对每段参数、结果目录和基准口径一致。

## 可见启动

`tools/Run-VisibleBacktest.ps1` 接收结构化任务，不再接收可拼接的原始命令或 V1.4 config。入口使用白名单，参数逐项转义。

```powershell
$runs = @(
  @{ Name = '2025'; EntryPoint = 'scripts/run_wufu_v52.py'; Arguments = @('<2025参数1>', '<2025参数2>') },
  @{ Name = '2026'; EntryPoint = 'scripts/run_wufu_v52.py'; Arguments = @('<2026参数1>', '<2026参数2>') }
)
& .\tools\Run-VisibleBacktest.ps1 -Runs $runs -LogPrefix 'wufu_formal' -DryRun
```

先用 `-DryRun` 检查最终 WSL 命令、日志路径和入口；确认无误后去掉 `-DryRun` 才会启动窗口。

启动器会：

- 解析当前 V2 WSL 根。
- 拒绝超过 4 条命令。
- 只接受白名单中的 V2 受控入口，并把参数作为独立 shell 字面量转义。
- 拒绝 `--in-process`，不接受可直接注入 Bash 的完整命令字符串。
- 为每段打开独立窗口。
- 设置 `PYTHONUNBUFFERED=1`，并把输出同时写入平台 `tmp/` 日志。

命令中的具体参数必须来自平台入口 `--help` 或实验预注册，研究库不提供虚构的通用参数。

## 巡检

主控启动后必须主动巡检，不能把监控责任交给用户：

- 前 5 分钟内报告启动状态和初步速度。
- 长回测每 1 至 2 分钟读取日志，说明当前阶段、日期、权益或平台原生进度。
- 若日志停止更新，检查 CPU、RSS、交换、资源租约和进程组，而不是立即认定策略慢。
- 完成必须以入口退出码、平台结果产物和进程组归零共同判断。
- 失败时记录实际命令、日志路径、退出码和最后进度。

## 后台与停止

确需后台运行时必须先记录：

```text
后台回测豁免：<原因>
进程标识：<pid或任务名>
日志路径：<平台内路径>
查看进度：<命令>
停止方式：<受控停止命令>
预计耗时：<duration>
```

停止回测应使用平台受控入口和进程组清理机制，不得只杀父进程留下孤立子进程。

## 历史说明
