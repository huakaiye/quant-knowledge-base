# 可视化分段回测规范

本规范是所有 Agent 启动回测时的默认流程，从 2026-07-02 起作为硬约束执行。它取代了过去"一个窗口跑所有段、进度看不见、进程被超时杀"的做法。

## 为什么需要本规范

过去回测反复踩三个坑：

1. **进度不可见**：工具调用的输出要等命令结束才一次性返回，中途主控和用户都看不到进度行。
2. **进程被超时杀**：主控的工具调用（无论前台还是 `run_in_background`）都有时长上限，超过就把回测 python 进程一并终止。
3. **混合窗口太乱**：多段塞进一个窗口，进度行交错，无法分辨哪段跑到哪。

本规范用"一年一段、一段一窗、实时滚动、自主巡检"彻底解决上述问题。

## 硬规则

### 1. 按自然年分段

回测区间默认按**自然年拆分**，每年一段：

- 跨年区间先拆成年度 config，再启动。例如 2021-07 至 2026-06 拆成 6 段：`2021H2`、`2022`、`2023`、`2024`、`2025`、`2026H1`。
- 单年区间（如只回测 2024）也按本流程启动，只是只有一段一个窗口。
- 不得把多年塞进一个 config 用一个窗口跑。

例外：仅当单段回测能在主控一次工具调用窗口内完成（如 smoke 测试，单月、单段、< 5 分钟）时，可直接前台跑，无需弹窗。

### 2. 一年一个独立窗口

每段回测启动时，**为该段弹出一个独立的 cmd 窗口**：

- 窗口标题 = 段名（年份或 `segN_<区间>`），便于区分。
- 每个窗口**只跑这一段**，进度行不与其他段混在一起。
- 窗口内直接前台运行 `run_v2_backtest.py`，进度行通过 `tee` 同时写盘 + 实时显示，**不得用 `tail -N` 截断**（截断会让进度看不见）。
- 窗口完成后不自动关闭，显示完成提示并等待回车，方便用户看最终结果。

### 3. 实时进度滚动

每个窗口内的回测必须实时显示进度：

- 启动前设 `PYTHONUNBUFFERED=1`，确保进度行立即刷新，不被 Python 缓冲。
- 进度行格式保持平台原生（`[进度] xx% | 日期 ... | 权益 ... | 成交 ...`）。
- 同时 `tee` 写入固定日志文件（`tmp/live_<段名>.log`），供主控巡检读取。

### 4. 主控自主巡检

回测在独立窗口跑起来后，**主控必须自主巡检，不得要求用户通知**：

- 启动所有窗口后，主控每隔 **2 分钟**读取一次各段日志末尾，报告进度快照。
- 巡检持续到**全部段完成**：判断标准是 `results/` 下对应段出现 `summary.json` 且 WSL 内 `run_v2_backtest` 进程数为 0。
- 完成后主控立即读取各段 `summary.json` 做结果汇总与分析。
- 不得采用"启动后等用户说跑完了再分析"的被动模式。

## 启动方式

使用研究库标准脚本，一行启动所有段（每段自动弹一个独立窗口）：

```powershell
powershell -ExecutionPolicy Bypass -File tools/Run-VisibleBacktest.ps1 -Configs @(
  "configs/research/<rd>/seg1_2021.json",
  "configs/research/<rd>/seg2_2022.json",
  "configs/research/<rd>/seg3_2023.json"
)
```

脚本内部为每个 config 弹一个 cmd 窗口，窗口标题取 config 文件名，进度实时滚动并写盘到 `tmp/live_<段名>.log`。

若需手工启动单段（调试用），命令模板：

```powershell
Start-Process cmd -ArgumentList "/k", "title <段名> && wsl -- bash -c `"cd '<platform_wsl>' && PYTHONPATH=src PYTHONUNBUFFERED=1 python3 src/run_v2_backtest.py --config <config相对路径> 2>&1 | tee tmp/live_<段名>.log; echo '====== <段名> 完成_本窗口可关闭 ======'; read`"
```

其中 `<platform_wsl>` 由 `tools/Get-QuantPlatformRoot.ps1 -Target Platform -Format WSL` 解析。

## 与既有规则的关系

| 既有规则 | 本规范的关系 |
| --- | --- |
| AGENTS.md 实时进度输出规则（2026-06-21） | 本规范是其升级版：进度不仅写盘，还实时显示在独立窗口，用户可直接看。`PYTHONUNBUFFERED=1 + tee` 仍保留。 |
| AGENTS.md 并行回测默认规则（2026-06-22） | 本规范改变启动载体：不再用 `run_parallel_backtest.sh` 把多段塞进一个进程树（其 `tail -1` 会截断进度），改为一年一窗独立启动。并行性由"多个窗口同时跑"实现，每段独立 python 进程。 |
| 平台协作规范 | 路径解析仍走 `tools/Get-QuantPlatformRoot.ps1`，本规范不改路径约定。 |

## 不适用场景

- **参数网格扫描**：当需要跑几十上百个 config（如 32 段 formal 矩阵）时，逐个弹窗不现实。此时仍用 `run_parallel_backtest.sh` 后台批量跑，主控巡检 `run.log`。本规范适用于"少量段、需人工观看进度"的场景（通常 ≤ 8 段）。
- **单段快速 smoke**：< 5 分钟、能在一次工具调用窗口内完成的，直接前台跑即可。
- **非 WSL 环境**：本规范的弹窗依赖 Windows cmd + WSL，纯 Linux 环境不适用。

## 巡检报告格式

主控每次巡检应输出简洁表格，便于用户一眼看清：

```text
=== 第 N 轮 HH:MM:SS ===
seg1_2021: [进度] 45% | 日期 2021-XX | 权益 XXXXX
seg2_2022: [进度] 62% | 日期 2022-XX | 权益 XXXXX
完成: 1/4
```

完成段用 `✅`，运行中用进度行，异常用 `❌` 并说明。
