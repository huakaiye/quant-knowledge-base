## 背景问题（已核实）

V2 平台现有 13 张主表存在系统性口径错配：

- 表名前缀是 `jq_`、配置里 `provider` 标的是 `jq`，但实际数据**全部**来自 xtdata 口径。
- 生产入口 `E:\xtquant\策略\xtdata_update_full.py` 走 xtquant 拉数，不是 jqdatasdk。
- 已确认的下游症状：
  - `jq_valuation` 的 PE/PB/PS 字段全空。
  - `jq_stock_info` 的行业分类全是 `None`。
  - 复权因子与聚宽不等价。

这是 [[02_研究方向/RD-20260707T135354Z-main-WUFU_五福闹新春ETF动量轮动复现与审计|WUFU 策略复现差异]] 的根因之一——复现差异中 4.66x 的倍数关系，部分来自复权因子口径偏差。本方向就是修复这个基础设施的工程。

## 三项架构决策（已确定）

1. **接入方式 = jqdatasdk 纯 API 直连**。不用离线导出兜底，所有数据（含分钟线）都走 jqdatasdk 实时拉取。好处是口径与聚宽官方完全一致、可自动续传、不存在二次同步漂移。
2. **隔离策略 = 新建 `jq_v3_*` 表 + `data_routing` 路由切换**。旧 `jq_*` 表保留不动，新数据写入 `jq_v3_*`，通过路由层切换读取源，可随时回滚到旧表。
3. **范围 = 全面接入**。不仅切回 13 张主表的口径，还要接入聚宽全部特有数据：北向资金、分红送转、可转债、融资融券、因子库等。分钟线也纯 API 拉取，不退化到离线补量。

## 当前研究信念

口径偏差是当前所有聚宽策略复现差异（包括 WUFU 的 4.66x）的最大可定位根因之一。把数据口径切回聚宽原生后，策略复现的数字才能和聚宽官方对齐，后续的超额收益分析、因子有效性判断才建立在可信基础上。阶段0的 benchmark 已经证明纯 API 直连在工期和配额上完全可行（1.7 天、配额占比 0.47%），不存在技术阻塞。

## 可观察预测

如果重构成功，应该能看到：

- `jq_valuation`（或其 v3 继任者）PE/PB/PS 非空，数值与聚宽官方一致。
- `jq_stock_info`（或 v3）行业分类非 None，与聚宽官方一致。
- 用聚宽官方策略代码回测，权益曲线与聚宽官方记录对齐。
- WUFU 等策略复现时，4.66x 这类倍数差异消失或大幅缩小。

## 竞争性解释

即使策略复现数字变好，也可能不是口径修复的功劳：

- 可能是参数在不同口径下恰好更优，而非口径本身正确（需做口径切换前后的 A/B 对照）。
- 可能是聚宽官方策略代码本身的执行细节（如下单时点、成交价）与回测引擎差异，而非数据口径。
- 分钟线口径切换后可能引入新的未来函数风险（前复权 vs 后复权的时点处理），需要独立审计。

## 证伪条件

出现以下情况时，本方向应 `revise` 或 `park`：

- 阶段1核心 13 表口径切换后，复现数字**没有**向聚宽官方靠拢（说明口径不是主因）。
- jqdatasdk 在全量历史拉取时出现无法绕过的速率/配额阻塞（阶段0已排除，但全量分钟线尚未实测）。
- `jq_v3_*` 路由切换导致大面积回测引擎报错且回滚成本过高（说明隔离设计有缺陷）。

## 给新手的方向解释

- **为什么有这个方向**：平台里 13 张表的名字和配置都写着"聚宽"，但数据其实来自另一个库（xtdata）。这导致 PE/PB/PS 是空的、行业分类是空的、复权因子和聚宽官方对不上。任何想精确复现聚宽策略的人都会被这个坑绊倒。
- **它和主策略是什么关系**：它不是某个策略的研究，而是所有策略共享的数据地基。地基偏了，上面所有策略的数字都不可信。WUFU 策略复现时出现 4.66x 倍数差异，部分就是复权因子口径偏差造成的。
- **当前最重要的证据**：阶段0已经做了一个聚宽数据拉取框架（jq_fetcher），实测证明用聚宽正式版账号纯 API 拉全部历史数据只要 1.7 天、配额够用 200 倍，技术上完全可行。
- **现在还不知道什么**：核心 13 表口径切回聚宽后，策略复现数字会不会真的向聚宽官方靠拢——这是阶段1要回答的问题。
