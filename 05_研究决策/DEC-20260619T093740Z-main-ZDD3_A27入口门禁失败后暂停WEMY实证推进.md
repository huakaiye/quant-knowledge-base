## 决策结论

`park`

## 这个节点是什么

A25/A26 已经证明当前涨幅、路径、成交额、成交量、13:09 成交形态和 ETF 涨停压力这些“本地可见字段”不能稳定解决 hard5 反弹误杀和追高/撤离问题。A27 进一步检查下一步真正该走的两类独立信息源：真实订单生命周期和外部注意力/盘口数据。检查结果是：当前本机没有可直接执行的入口。

## 相比上一个节点改变了什么

- DNLA 只说“不再扩当前可见字段，后续只走真实订单生命周期或外部注意力/微观结构”。
- ZDD3 补充了入口门禁：当前 QMT 路线仍被客户端进程不可见阻塞，本地也没有非空 tick、盘口、融资、情绪、搜索或注意力研究面板。
- 因此 WEMY 不只是“不该继续调当前字段”，而是“在 QMT 登录或新增外部数据源前暂停实证推进”。

## 支持证据

- A27 QMT 只读诊断输出 `overall_status=qmt_client_process_not_found`，唯一 required failure 为 `qmt_process_found`。
- QMT 诊断同时显示 `userdata_fresh_gate=true`、`xtquant_modules_importable=true`，说明当前阻塞集中在客户端进程/登录状态，而不是配置或 Python 包缺失。
- ClickHouse 候选表只有 `quant.jq_daily_limit_status_full`，没有非空 tick、orderbook、depth、margin、sentiment、search、attention、dragon、north 等新表。
- 本地文件名候选 7689 个，但强候选过滤后只剩 `jq_research_probe_get_ticks.csv` 和 `jq_research_notebook.html`。
- `jq_research_probe_get_ticks.csv` 只有 995 行，是迁移探针，不是覆盖 A25/A26 178 个事件的正式研究面板。

## 反对证据

- JQ tick 探针证明未来可能另开数据建设实验，不代表 tick 路线失效。
- QMT userdata 最近仍有更新；用户手动启动并登录 QMT 模拟客户端后，真实 dry-run JSON 路线可能恢复。
- A27 没有测试任何新策略规则，所以不能证明订单生命周期或外部注意力机制没有 alpha。

## 边界

本决策不能说明“订单生命周期无效”，也不能说明“外部注意力或盘口数据无效”。它只说明当前本机没有可审计、可复现、覆盖足够的正式数据入口。后续如果 QMT 客户端可见并能生成真实 `live_dry_run_once.json`，或新增外部注意力/逐笔/盘口/融资融券数据源，应新开实验重新预注册。

## 后续动作

- WEMY 保持 `park`，不继续扫日频、分钟、成交额、成交量、ETF 涨停压力或状态阈值。
- 本决策原本保留 QMT 作为可能入口；后续 HJGJ 已根据用户判断排除 QMT 主路线。
- 若用户希望继续 WEMY，只做非 QMT 外部注意力/盘口路线的数据建设门禁：确认数据源、时间戳可得性、覆盖率、费用权限、未来函数边界和与 A25/A26 事件的可连接性，再新开正式信号实验。
